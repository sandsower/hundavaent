# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or exposed credential.
Use GitHub's private vulnerability reporting feature for this repository.
Include the affected component, reproduction steps, impact, and any suggested mitigation.

## Supported versions

Security fixes target the current `main` branch until tagged releases establish a broader support policy.

## Secrets and production data

The repository accepts only browser-safe public configuration examples.
Credentials, production exports, prospect inventories, private planning artifacts, and operator reports must remain outside Git.
